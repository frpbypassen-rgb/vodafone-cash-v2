# عرض الشركات والوكلاء في الإدارة

دليل الحسابات يعرض العملاء والشركات والوكلاء ببطاقات موحدة: بطاقة في صف الهاتف، وبطاقتان في العرض المتوسط، وثلاث بطاقات على الكمبيوتر. تُبرز البطاقة الاسم والحالة والرصيد بثلاث منازل عشرية، مع رقم الحساب القابل للنسخ والهاتف والمدينة. البحث وفلاتر الكل/النشط/المتوقف وتقسيم النتائج إلى صفحات من 24 حسابًا متاحة للأقسام الثلاثة. القائمة لا تجلب توكن الشركة أو أسرار الدخول؛ تظهر أدوات الحساب والموظفين والتكاملات والوثائق في قائمة الإجراءات حسب الصلاحية. إنشاء الحسابات يرتبط بمسار طلبات التسجيل الحالي.

ملف الشركة أو الوكيل يستخدم `/company/:id` أو `/user/:id` نفسه، مع `tab=ledger|finance|staff|settings|profile|audit`. الصفحة تعرض ملخصًا صغيرًا وأزرار التعديل والإيداع، ثم القسم المطلوب فقط. على الهاتف يُختار القسم من قائمة، وعلى الكمبيوتر من ألسنة. الروابط القديمة مثل `#owner-email-otp` و`#merchant-integration-access` و`#company-pricing` تفتح القسم الموافق.

## السلوك والحدود

- السجل المالي يعرض 20 سجلًا في الصفحة، مع البحث ورقم العملية والفترة بتوقيت ليبيا والحالة وتفاصيل قابلة للفتح. استعلام الملكية وإخفاء عمليات العملاء الفرعيين يستخدمان سياسة الإدارة الأصلية. عكس التسوية يظهر فقط للسجلات التي يقرّها فحص القابلية للعكس الموجود.
- الموظفون يعرضون 20 حسابًا في الصفحة من الشركة/الوكيل المحدد، مع البحث وروابط المحرر الموجودة؛ لا تُجلب كلمات مرور أو أسرار MFA. لا تظهر حسابات عملاء الوكلاء الخاصة ضمن دليل الإدارة.
- إعدادات البوابة تستخدم اللوحة المشتركة الحالية؛ تظل صلاحيات API وWebhooks والبريد وTelegram وإشعارات الويب محكومة بنفس خدماتها وإصدارات الحفظ.
- البيانات والأمان تعرض بيانات المنشأة وبريد OTP وحالة Authenticator وأدوات رقم الحساب والحالة. التعديل يبقى في المحرر الموجود، وتأكيد MFA يبقى في مساره الخاص.
- سجل التعديلات متاح للإدارة الرئيسية فقط، ويعرض اسم المنفذ والوقت ونوع التغيير والحقول المتغيرة دون نسخ `oldData` و`newData` أو بيانات الأجهزة أو الأسرار.
- نماذج الإيداع والحد الائتماني والمستوى والأسعار وتغيير المفتاح والحالة وعكس التسوية تبقي أسماء الحقول ومسارات POST والتحقق الأصلي. أضيفت رموز CSRF صريحة للنماذج المعروضة. لا توجد تغييرات على منطق حساب الأرصدة أو تنفيذ التحويلات.

لا يجلب قسم الموظفين السجل المالي، ولا تجلب البيانات والتكاملات سجلات الموظفين أو التدقيق. تستعلم القائمة ضمن `adminAccountScope`، وتستخدم التفاصيل حدود الحساب الحالية. لا توجد اعتماديات أو ترحيلات بيانات جديدة.

## التحقق

```powershell
npx jest tests/adminMerchantDetail.test.js tests/adminMerchantTabLoad.test.js tests/adminAccountDirectoryService.test.js tests/adminAccountDetailScope.test.js tests/adminAccountVisibilityService.test.js tests/accountIntegrationPdfContract.test.js --runInBand
node scripts/checkAdminMerchantBrowser.js
node scripts/checkPortalSettingsSyncBrowser.js
```

فحص المتصفح مقيد بقاعدة المعاينة المحلية `ahram_company_mobile_demo_v2` وخادم `127.0.0.1:4577`، ويتطلب `MONGO_URI` و`PUPPETEER_EXECUTABLE_PATH`. ينشئ حسابات وسجلات تجريبية معزولة ثم يزيل معرفاتها الدقيقة. يفحص البحث والحالة والصفحات وقائمة الإجراءات وقائمة الإدارة والأقسام وروابطها القديمة ونماذج الرصيد والأسعار والتكاملات، بعروض 320 و390 و430 و1366 وبالوضعين النهاري والليلي. لا ينفذ حركات مالية أو حذف حسابات عبر واجهات التطبيق ولا يرسل رسائل خارجية.

يُحظر الاتصال الخارجي في اختبار المتصفح؛ يبدأ جمع أخطاء صفحات الميزة بعد مغادرة لوحة القيادة الموجودة، التي تعتمد رسومها على Chart.js الخارجي. هذا الفحص لا يدّعي اختبار لوحة القيادة أو تسليم رسائل البريد وTelegram فعليًا.


## منفذو وبوتات التنفيذ

تستخدم صفحة `/executors` نفس مكونات البطاقات المتجاوبة، مع بحث محلي وفلاتر الحالة ونوع المنفذ. تبقى أرصدة الخدمات منفصلة، ورصيد API لقطة محفوظة لدى المزود مع وقت الفحص؛ فتح الدليل لا ينفذ اتصالات بالمزود. إعداد الخدمات قابل للفتح، وروابط الاختبار والتعديل والأرشفة ضمن قائمة الإجراءات. الأرشيف يعرض بطاقات للقراءة مع العمليات المحفوظة، وتبقى مسارات الإنشاء والتسوية والأرشفة والتحقق من الصلاحيات كما هي.


## ملف المنفذ اليدوي والإداري

صفحة `/executor/:id` للمنفذ اليدوي والإداري تبدأ بملخص الرصيد وأعداد العمليات، ثم `tab=ledger|operations|staff|settings`. الهاتف يستخدم قائمة اختيار والكمبيوتر تبويبات. نماذج التسوية وسياسات التنفيذ والخدمات والموظفين تحافظ على مساراتها وصلاحياتها وCSRF؛ روابط `#settlementForm` و`#executor-status` تفتح القسم الموافق. غرفة API والأرشيف يحتفظان بمساريهما المتخصصين.

`adminExecutorDetailService` يقرأ حركات المنفذ كاملة مع ترقيم 20 حركة. السجل المالي يطابق مصادر احتساب الرصيد الحالية، ويستبعد `external_balance`، ويجمع الإيداع والخصم والتنفيذ لكل خدمة على حدة. أرصدة ما قبل/بعد الحركة تشمل الأموال الموزعة للخارجيين، ولا تساوي دائمًا الرصيد الخاص. حساب الرصيد التراكمي يتم بواسطة MongoDB `$setWindowFields` (MongoDB 5+)، قبل البحث وتصفية الفترة، حتى لا يُعاد رصيد البداية إلى الصفر. تبقى بيانات العمليات ومراجعات API منفصلة.
