# جاهزية بوابة التنفيذ للإنتاج

التاريخ: 2026-10-06. النطاق: فرع العمل المحلي `codex/executor-financial-safety` بجميع تعديلاته غير الملتزمة. لم يحدث دفع حقيقي أو اتصال بقاعدة إنتاج أو دمج أو نشر.

## النتيجة

النسخة **مرشح إصدار ناجح محلياً**، وليست موافقة نهائية على النشر قبل اجتياز بوابات البيئة أدناه. نجحت المجموعة الكاملة: 230 ملف اختبار و1838 اختباراً بلا فشل. نجح ESLint وTypeScript وفحص المعمارية وPrettier و`git diff --check`. تدقيق تبعيات الإنتاج يعرض صفراً من الثغرات المعروفة.

## الإصلاحات المنفذة في هذه الجولة

- أصبح إنشاء طلب الإيداع يحفظ العملية وتذكرة الدعم والرابط بينهما داخل معاملة Mongo واحدة. فشل أي خطوة يعيد السجلات وينظف الملفات، ولا يفشل الطلب بعد نجاح الحفظ لمجرد تعطل الإشعار.
- أصبحت أرشفة شركة التنفيذ وتعليق موظفيها وإزالة قواعد التوجيه وحدة ذرية، ولم تعد أخطاء تنظيف الإعدادات تُخفى. إعادة طلب أرشفة حساب قديم تصلح آثاره الناقصة.
- أضيف صندوق آثار لاحقة دائم لإكمال عمليات المنفذ. يُحفظ سجل العمل داخل معاملة الإكمال، ثم يعيد التدقيق والإشعارات فقط. لا يعيد العامل الدفع أو الخصم أو تغيير الحالة، ويرفض أي عملية ليست `completed`.
- عُزلت إشعارات الدعم اللحظية داخل غرفة `admin:support` بعد التحقق من جلسة الإدارة وصلاحية `support.read`؛ لم تعد بيانات التحديث تُبث لكل Socket متصل.
- وُحد التحقق من صور الإثبات والإيداع والدعم: حد بايتات قبل فك Base64، تطابق النوع الحقيقي مع MIME، وحدود الأبعاد وعدد البكسلات. تُرفض الملفات التالفة أو ذات الامتداد المضلل.
- وُحد الحد الأدنى لكلمات مرور حسابات التنفيذ الجديدة وإعادة الضبط إلى 8 أحرف. لا تُبطل كلمات المرور الحالية.
- رُفعت `compression` و`proxy-addr` و`@fastify/busboy` إلى الإصدارات المصححة، وثُبتت الإصدارات الحساسة في lockfile.

## السلامة المالية

- لم تتغير معادلات التسعير أو سعر الصرف أو العمولات في هذه الجولة.
- اختبار replica-set الحقيقي تحقق من ثبات الأرصدة، منع إعادة الخصم، تراجع إنشاء الإيداع عند فشل التذكرة، وتراجع الأرشفة عند فشل تنظيف الإعدادات.
- الآثار اللاحقة تستخدم مفاتيح منع تكرار للتدقيق والإشعارات والويب هوك والسجل المحاسبي؛ إعادة المحاولة لا تنفذ الحركة المالية.

## بوابات النشر الإلزامية

لا يُنشر قبل تحقق مسؤول البيئة من الآتي:

1. نجاح CI على الرأس النهائي في Node 20 وNode 22 وبناء Docker. لم تتوفر هذه الأدوات محلياً على هذا الجهاز.
2. تشغيل `npm run check:executor-readiness` على قاعدة الإنتاج بصلاحية قراءة، والتأكد من replica set وTTL وفهارس `executorcompletionoutboxes`.
3. وجود نسخة احتياطية قابلة للاستعادة وخطة rollback مجربة، ثم نشر تدريجي مع مراقبة outbox والأخطاء.
4. التأكد من تشغيل عامل الآثار اللاحقة في كل نسخة تطبيق، وعدم وجود سجلات `pending` قديمة أو `processing` عالقة بعد النشر.
5. عدم تنفيذ أي دفع تجريبي في الإنتاج؛ smoke test الإنتاج يقتصر على القراءة والجلسات أو بيانات اختبار معزولة معتمدة.

## مخاطر غير حاجبة متبقية

- قائمة المهام الحية ومحادثات الدعم القديمة ما زالت تحتاج pagination كاملة لتقليل الذاكرة في الأحجام الاستثنائية. فرض حد صامت الآن قد يخفي مهمة مالية، لذلك لم يُطبق دون واجهة تحميل صفحات مكتملة.

- أدوات الاختبار تحتوي تنبيهات dependency متوسطة؛ اقتراح npm الحالي يتطلب تغييرات كاسرة، بينما تدقيق إنتاج `--omit=dev` نظيف.
