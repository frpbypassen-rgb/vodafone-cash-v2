# مراجعة تسليم التشغيل

الحالة: التشغيل الكامل المتوازي المقترح سُحب، ولم يُنفّذ على الإنتاج. الإقلاع الخاص نجح، لكنه لا يجيز تشغيل مستهلكي العمل المشترك.

المقترح الذي خضع للمراجعة كان تشغيل full على منفذ ثانٍ مع تعطيل المجدولات والبريد والويبهوكس، مع بقاء القديمة خادمة. العقد: لا تأثير مالي ولا إرسال مكرر أو عمل مفقود ولا تغييرات غير مراجعة بسبب الإقلاع. المراجعة جرت بسياق مستقل وللقراءة فقط، والمستخدم اختار تجاوز مراجعة CLI إضافية بنموذج آخر.

نطاق المراجعة هو المصدر المتتبع المتاح محليًا. المرشح البعيد يتضمن أيضًا تعديلات عمولة الخادم التي جرى حفظها ودمجها؛ فحص تحميلها الساكن لا يعادل مراجعة دلالاتها المالية كاملة. ملاحظة Map أدناه تخص نسخة المستودع ويجب تأكيد سلوك النسخة المعدلة قبل أي تصميم للتوازي. مسارات بدء العمال في app.js وصناديق الآثار لم تكن ضمن قائمة التعديلات المحلية المعلنة.

## النتائج والتصرف

صُنفت النتائج التالية كمسائل صحيحة تستلزم تغيير المقترح؛ لا تُعد إثباتًا على حدوث فساد مالي في الخدمة الحالية:

| النتيجة | الدليل في المصدر | التصرف |
|---|---|---|
| BullMQ يبدأ استهلاك تحويلات مشتركة قبل الجاهزية | `app.js:535` و`services/bullQueueService.js:71` | سحب اقتراح تشغيل نسخة full بجانب القديمة |
| علم المجدولات لا يعطل مستهلكي التسويات والمطابقات والنسخ الاحتياطي | `services/bullQueueService.js:101` | لا اعتبار تعطيل علم واحد دليلًا على غياب العمل المالي |
| Push وصندوق آثار الإكمال يبدأان مباشرة ويعيدان ضبط سجلات قديمة | `app.js:579` و`services/executorCompletionOutboxService.js:100` و`services/executorPushNotificationService.js:979` | لا تشغيل مستهلك ثانٍ قبل تسليم الملكية |
| مطالبات صناديق الآثار لا تحمل fencing token وتُسترد بعد مدة | `services/executorCompletionOutboxService.js:46` و`:78`، و`services/executorPushNotificationService.js:860` | غياب دليل كافٍ على سلامة التداخل؛ يلزم اختبار انتهاء المطالبة والاسترداد |
| تسلسل العمليات لنفس المزود محلي داخل Map | `services/apiProviderReconciliationService.js:459` | مطالبة الدفع لكل معاملة لا تكفي لإسناد تدقيق رصيد عمليتين مختلفتين بالتوازي |
| مهمة مكررة قد تحول إرسالًا جاريًا إلى unresolved | `services/providerDispatchClaimService.js:268` | لا إعادة ضخ أو تكرار مهام أثناء الانتقال |
| تهيئة التنبيهات والفهارس ومرآة التقارير قد تنفذ آثارًا رغم الأعلام المقترحة | `app.js:540` و`:564`، و`services/unifiedReportService.js:232` | فحص جميع مسارات الإقلاع قبل تفعيل المرشح |
| حاجز امتلاك المنفذ لا يحمي عند استخدام منفذ ثانٍ | `services/httpStartupService.js:15` | الإقلاع على منفذين ليس سياج ملكية للعمال |

بعض اختبارات هذه المسارات تستبدل Mongo أو event bus أو worker constructor بمضاعفات اختبار. الاختبارات المالية الحقيقية الحالية مفيدة، لكنها لا تختبر عمليتي تطبيق كاملتين وآثار كل النقل الخارجي تحت استرداد المطالبات. لذلك لم يُستخدم نجاح الفحص الخاص أو الاختبارات المخصصة كتصريح بالنقل العام.

## قرار التشغيل

ثبت من جهاز خارج الخادم أن DNS النطاق يشير إلى عنوان الخادم المعلن، وأن HTTP على المنفذ 3000 يعيد PID 6764 الجاهز نفسه. لم تُرسل بيانات مصادقة أو طلبات مالية في هذا الفحص؛ جرى GET للجاهزية فقط.

لا نعرف بعد هل توجد شركات أو تطبيقات موزعة تستخدم هذه الوجهة مباشرة. سجل الطلبات الحالي لا يحفظ Host، وإثبات وجود عملاء مباشرين أو غيابهم لا ينتج من سجل مسار/IP وحده. اختار المستخدم تأجيل النقل والإبقاء على عدم الانقطاع حتى التحقق من الروابط. لم تُقبل نافذة انقطاع، ولم تُوقف القديمة أو تُغير قواعد IIS/الجدار الناري.

يلزم قبل عرض تنفيذ النقل: تحديد كل وجهات الدخول، وإثبات طريقة تصريف الطلبات والمهام وتسليم التنفيذ دون تداخل، وتجربة الرجوع في بيئة معزولة. قائمة حسابات API وعناوين Flutter الثابتة أدوات جمع معلومات وليست موافقة انتقال أو إثباتًا لاستخدام النسخ المنشورة.
