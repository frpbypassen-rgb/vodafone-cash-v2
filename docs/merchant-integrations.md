# تكاملات الشركات والوكلاء

## الإدارة والاستخدام

من صفحة بيانات الشركة أو الوكيل في الإدارة، يستطيع المدير الأساسي تفعيل API وWebhooks بصورة مستقلة من مربع «تفعيل التكاملات الخارجية». تُحفظ الإعدادات على الحساب نفسه. لا يستطيع صاحب الحساب تفعيل الخدمة إداريًا لنفسه.

في البوابة: المزيد ← الإعدادات ← التكاملات. تظهر أدوات المفاتيح لصاحب الحساب فقط، مع تأكيد كلمة المرور الحالية عند الإصدار أو التغيير أو الإيقاف. القفل يتبع حالة الإدارة؛ يمكن تحديثها بالزر، وتتحدث كل 15 ثانية أثناء عرض القسم. الموظفون ومديرو التشغيل والمحاسبون لا يديرون بيانات الربط.

يُعرض التوكن كاملًا مرة واحدة. يُحفظ SHA-256 للتوكن العشوائي الجديد فقط، مع آخر ستة أحرف وتاريخ الإصدار. تغيير المفتاح يستبدل البصمة ويمسح المفتاح القديم في عملية قاعدة بيانات واحدة. إيقاف المفتاح يمسح البصمة والمفتاح القديم ويضبط حالة الإلغاء. إعادة تفعيل API من الإدارة لا تعيد مفتاحًا ألغاه صاحبه. لا تُخزّن المفاتيح في localStorage ولا سجل التدقيق، ولا تُعاد ضمن استعلام الحالة. تُمسح قيمة العرض عند مغادرة الصفحة.

## التوافق والتفعيل عند النشر

الإعدادان `integrationAccess.apiEnabled` و`integrationAccess.webhooksEnabled` مغلقان افتراضيًا، بما في ذلك السجلات التي لم تُضبط بعد. **الحسابات التي تستخدم التكاملات حاليًا تحتاج تفعيلًا صريحًا من الإدارة عند اعتماد هذا الإصدار.** إيقاف الحساب العام يمنع الاستخدام أيضًا. لا يجري التطبيق تعديلًا جماعيًا على الحسابات.

تظل مفاتيح `ClientCompany.token` و`User.apiToken` القديمة مقبولة بعد التفعيل الإداري فقط، حتى أول تغيير أو إلغاء. بعد التغيير تُحذف القيمة القديمة وتُستخدم البصمة؛ لا يوجد رجوع تلقائي إلى مفتاح سابق. تدوير المفتاح من الإدارة يستخدم المنطق نفسه ويعرض القيمة الجديدة مرة واحدة. وثيقة PDF لا تسترجع المفتاح المحفوظ كبصمة ولا تولّد بديلًا عن مفتاح ملغى؛ يحتفظ المستخدم بالمفتاح عند إصداره.

لا تشمل عملية الإبطال طلبًا اجتاز المصادقة وبدأ تنفيذه بالفعل. كل طلب لاحق يتحقق من قاعدة البيانات دون ذاكرة مؤقتة للمفاتيح أو لتفعيل الإدارة.

## المسارات

| الوظيفة | المسار |
|---|---|
| حالة التكاملات | `GET /client/api/integrations` أو `/agent-portal/api/integrations` |
| إصدار / تغيير التوكن | `POST …/api/integrations/rotate` مع `currentPassword` |
| إلغاء التوكن | `POST …/api/integrations/revoke` مع `currentPassword` |
| تفعيل الإدارة | `POST /company/:id/integrations` أو `/user/:id/integrations` |
| API الخارجي | `/api/v1/merchant` وترويسة `x-api-key` |
| إدارة Webhooks | `/client/integrations/webhooks` أو `/agent-portal/integrations/webhooks` |

طلبات البوابات والإدارة محمية بجلسة وصلاحيات وCSRF. تغيير المفاتيح محدود بعشر محاولات خلال 15 دقيقة لكل حساب مستخدم. الفصل بين الشركات والوكلاء والمستأجرين يُراجع في الخادم.

## تسليم Webhooks

تشمل الإدارة: الرابط والأحداث، تشغيل نقطة الاتصال وإيقافها، تدوير سر توقيعها، اختبار الاتصال، وسجل المحاولات وإعادتها. يحتاج التسليم إلى `MERCHANT_WEBHOOK_WORKER_ENABLED=true` في بيئة تشغيل مُهيأة. اختبار الاتصال يرسل حدثًا تجريبيًا يحمل `test: true`، ولا ينشئ تحويلًا ماليًا.

يُراجع تفعيل الإدارة قبل إضافة الأحداث وقبل إرسال طلب HTTPS، بما في ذلك إعادة المحاولات اليدوية والإدارية. عند الإيقاف لا تُرسل الأحداث المنتظرة؛ تُعلَّم المحاولة بسبب `WEBHOOK_DISABLED_BY_ADMIN`. يمكن إعادة المحاولة يدويًا بعد التفعيل. إرسال بدأ بالفعل لا يمكن استرجاعه.

الرابط يجب أن يكون HTTPS عامًا. تُرفض العناوين المحلية والخاصة، وتُثبّت وصلة HTTPS على نتيجة DNS التي تم التحقق منها لمنع إعادة ربط العنوان؛ لا تُتبع التحويلات. يُستخدم HMAC SHA-256 مع الوقت والنص الفعلي للطلب. التسليم قد يتكرر؛ يجب على المستقبِل إزالة التكرار باستخدام `x-ahrampay-event-id`.

```powershell
npx jest tests/merchantIntegrationAccess.test.js tests/merchantIntegrationRoutes.test.js tests/merchantWebhookService.test.js tests/merchantWebhookVisibility.test.js --runInBand
node scripts/testAgentPortal.js --silent

npm run check:architecture
node scripts/checkMerchantIntegrationsBrowser.js
```

فحص المتصفح مقيد بـ `http://127.0.0.1:4577` وقاعدة `ahram_company_mobile_demo_v2` المحلية. يحتاج `MONGO_URI` و`COMPANY_DEMO_PASSWORD` ومسار المتصفح `PUPPETEER_EXECUTABLE_PATH`. يختبر التفعيل، التغيير، الإلغاء، وفتح Webhooks للشركات والوكلاء، ثم يعيد إعدادات حسابات التجربة ومفاتيحها السابقة. لا يُستخدم على الإنتاج.

اختبارات التسليم تحاكي خادم HTTPS؛ لا تؤكد إمكانية الوصول إلى وجهة العميل الفعلية. زر الاختبار في الصفحة هو وسيلة التحقق من وجهة يحددها صاحب الحساب عند التفعيل.
