# خطة استقرار الإنتاج والانتقال مع استمرار الخدمة

تاريخ الإعداد: 2026-10-27. البروكسي بحسب المستخدم: IIS/ARR أو Plesk على Windows.

## النطاق وحالة التنفيذ

الهدف إصلاح تعارض العمليات والمنفذ 3000، وصيغة عنوان IP، وتحذيرات Mongoose، وتشخيص رفض توكنات الهاتف، مع الحفاظ على التحويلات والجلسات والإيصالات.

هذه خطة مستقلة؛ لا تستبدل مهام بوابة الشركات في `tasks/`. التنفيذ المحلي لا يعني النشر على الإنتاج. الخادم الحي بعيد، ولا يملك هذا السياق وصولًا مباشرًا إلى إدارته. لا تُنفّذ أوامر إيقاف أو إعادة تشغيل أو تعديل بروكسي أو قاعدة إنتاج قبل الحصول على جرد الخادم وتحديد النسخة الخادمة.

## أدلة التشخيص

- السجل المرسل أظهر `EADDRINUSE` واختلاف PID في PM2 عن مستمع 3000. هذه الأرقام تاريخية ولا يجوز استخدامها لاحقًا كأهداف للإيقاف.
- تحذيرات Mongoose تتعلق بإرجاع المستند بعد التحديث، وبعضها من عملية قديمة.
- بعض طلبات الهاتف تصل بعنوان IPv4 مع منفذ وتُرفض مصادقة طلبات أخرى بـ401/403. لا يكفي ذلك لإثبات سبب رفض التوكن.
- الكود الحالي يربط HTTP قبل بدء العمال، ويحتوي مفاتيح منفصلة للعمال والمجدولات والويبهوكس.

## الثوابت

1. تظل النسخة التي تخدم المستخدمين تعمل حتى نجاح البديل وتصريف الطلبات والمهام.
2. لا تغيير للأرصدة أو مبلغ التحويل أو حالات التنفيذ أو مفاتيح التوقيع والتشفير أثناء إصلاح التشغيل.
3. لا حذف للمهام أو إعادة إرسال دفعات مالية أو إلغاء جماعي للتوكنات.
4. لا تعطيل للمصادقة أو تحديد الطلبات أو التحقق من الأجهزة.
5. تبقى تعديلات عمولة API الموجودة على الخادم محفوظة ويُختبر دمجها في الإصدار المرشح.

## التسلسل ومعايير القبول

### 1. الجرد دون تغيير التشغيل

- [ ] تشغيل فحص قراءة فقط للعمليات والمنافذ وPM2 والخدمات وIIS والمهام المجدولة وإصدارات الأدوات.
- [ ] تحديد PID الخادم الفعلي ودليل الإصدار وPM2_HOME ومصدر التشغيل التلقائي والبروكسي الفعلي.
- [ ] توثيق مكان إعدادات توجيه الموقع وWebSocket وكيفية تعديل الوجهة دون إعادة تشغيل IIS كله.

القبول: خريطة واضحة للتشغيل دون قتل عملية أو عرض كلمات مرور أو توكنات.

### 2. إصلاحات واختبارات محلية

- [ ] تطبيع IPv4:port وصيغ IPv6 دون الثقة بترويسات غير موثوقة، واستخدام مفتاح تحديد طلبات مناسب لـIPv6.
- [ ] جعل ثقة البروكسي قابلة للتحديد الصريح مع الحفاظ على الإعداد الافتراضي الحالي إلى حين تأكيد بنية الخادم.
- [ ] تحديث خيارات Mongoose القديمة بعد مراجعة الاستدعاءات والحفاظ على المستند المعاد والجلسة وupsert والمعاملات.
- [ ] اختبار بدء نسختين على المنفذ نفسه: النسخة الخاسرة لا تبدأ عمالًا أو مجدولات.
- [ ] تشخيص 401/403 باستخدام رموز الخطأ ومطابقة مفاتيح وإعدادات البيئة والوقت دون تسجيل التوكنات أو تغيير صلاحيتها.

القبول: الاختبارات الأمنية والمالية والاسترجاع وعدم تكرار المعاملات ناجحة. لا اتصالات مالية حقيقية في الاختبارات.

### 3. إصدار مرشح مستقل

- [ ] تجهيز إصدار منفصل على منفذ داخلي حر، مثل 3001، دون تعديل ملفات النسخة الخادمة.
- [ ] مطابقة إعدادات الجلسات ومفاتيح التوقيع والتشفير وMongoDB وRedis؛ التحقق من دعم MongoDB 5+ للسجل المالي.
- [ ] تعطيل العمال والمجدولات وإرسال الويبهوكس في المرشح خلال الفحص فقط. لا تُعطّل اتصالات تنفيذ لازمة عشوائيًا.
- [ ] فحص الجاهزية والدخول والتقارير وملف المنفذ وعمولة API وWebSocket، بقراءة أو حسابات اختبار مناسبة.

القبول: المرشح جاهز ولا يستهلك أو يرسل عملًا ماليًا بالتوازي أثناء الفحص.

### 4. التحويل عبر IIS/ARR أو Plesk

- [ ] حفظ نسخة من إعدادات التوجيه وإثبات طريقة الرجوع.
- [ ] اختبار آلية التحويل الفعلية على بيئة معزولة؛ لا افتراض أن `iisreset` أو `pm2 restart` انتقال بلا انقطاع.
- [ ] تحويل الوجهة تدريجيًا إن دعمها التكوين، مع إبقاء العناوين العامة وروابط المزودين ثابتة.
- [ ] الإبقاء على النسخة القديمة لخدمة الطلبات والاتصالات القائمة حتى تصريفها.
- [ ] تسليم العمال والمجدولات مع فحص الأقفال والمهام الجارية ومنع تكرار الخصم والإرسال، ثم إيقاف القديمة تدريجيًا.

القبول: استمرارية الطلبات والجلسات، عدم تكرار أو فقدان العمل المالي، وتطابق وجهة الموقع مع الإصدار المقصود. التنفيذ يعتمد على نتيجة جرد الخادم؛ لا ضمان بانقطاع صفري باستخدام عملية fork واحدة وحدها.

### 5. المراقبة والرجوع

- [ ] مراقبة الجاهزية وتكرار إعادة التشغيل وEADDRINUSE و401/403 وزمن الطلبات والطوابير لمدة أولية 15–30 دقيقة.
- [ ] الرجوع بالتوجيه للإصدار السابق عند تجاوز مؤشرات الخطأ، مع تنسيق ملكية العمال.
- [ ] لا استعادة لقاعدة البيانات أو عكس معاملات صحيحة عند الرجوع بالكود.
- [ ] اعتماد إعداد الإقلاع وPM2 بعد ثبوت الاستقرار، وحفظ السجلات السابقة مع تمييز الوقت وPID.
