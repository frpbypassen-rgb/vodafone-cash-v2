# تشغيل بوابة الشركات للهاتف والتحقق منها

## الحدود التشغيلية

تستخدم الشركات المسارات `/client/` وصلاحيات `ClientEmployee`، مع أصول هاتف مستقلة في `public/css/company-mobile/` و`public/js/company-mobile/`. تبقى صفحات الوكلاء على `/agent-portal/`؛ لا تعني مطابقة العرض منح الشركات صلاحيات إدارة عملاء الوكالة.

التحقق من الصلاحيات في الخادم. تخصيص عرض التقارير لموظف حديث لا يجعله مالكًا، وتعديل صلاحيات الموظف يغيّر `sessionVersion` لإبطال جلساته السابقة. طلبا تعديل الصلاحيات المتزامنان يخضعان لرقم النسخة.

## الإعدادات المطلوبة

تفعيل API وWebhooks وإدارة التوكنات موثقة في [تكاملات الشركات والوكلاء](merchant-integrations.md). يتطلب الإصدار تفعيل الخدمة لكل حساب من الإدارة قبل قبول طلبات الربط.

| الوظيفة | الإعداد |
|---|---|
| رموز تأكيد البريد والكشوف | `SMTP_HOST`، `SMTP_PORT`، `SMTP_SECURE`، `SMTP_USER`، `SMTP_PASS`، `SMTP_FROM`؛ و`SESSION_SECRET` قوي لتجزئة رموز التأكيد |
| العامل اليومي | يعمل في الإنتاج؛ يوقفه `COMPANY_REPORT_EMAIL_ENABLED=false`. موعده 00:05 بتوقيت `Africa/Tripoli` عن اليوم السابق، للحسابات المؤكدة التي ما زالت مؤهلة |
| تيليجرام | `TELEGRAM_BOT_TOKEN` لبوت `Ahrampay_bot` و`TELEGRAM_WEBHOOK_SECRET`، وWebhook عبر HTTPS. لا تُطبع هذه القيم |
| PDF | تثبيت متصفح مدعوم وإتاحة مساره عبر `PUPPETEER_EXECUTABLE_PATH` عند الحاجة |

تؤخذ الشركة من الجلسة عند تنزيل التقرير، وتُستخدم فترة تقارير الإدارة نفسها. التقارير تعتمد توقيت ليبيا وتُرفض التواريخ غير الصالحة دون إلغاء جلسة المستخدم.

الاشتراكات والتسليمات في `CompanyReportEmail` و`CompanyReportEmailDelivery`، واتصالات البوت في `CompanyTelegramConnection`. تتهيأ الفهارس عند بدء التطبيق. تبقى سجلات التسليم غير المؤكد دون إعادة إرسال تلقائية لمنع التكرار.

## الحساب التجريبي

استخدم قاعدة محلية منفصلة تحتوي تسميتها على مقطع `demo` أو `test`، مثل `ahram_company_mobile_demo_v2`. يرفض السكربت المضيف البعيد وقواعد الإنتاج المعروفة، ولا تُعد معاملات رابط الاتصال دليلًا على أن القاعدة تجريبية.

زوّد `MONGO_URI` و`SEED_COMPANY_DEMO_PASSWORD` من البيئة ثم نفّذ:

```powershell
node scripts/seedLocalCompanyMobileDemo.js
```

ينشئ البذر ستة حسابات و25 معاملة تجريبية، ويعيد استخدام السجلات المالية الموجودة عند التكرار. لا يحتوي المصدر على كلمة المرور. لا تشغّل سكربت البذر على قاعدة التشغيل.

## فحوص قابلة لإعادة التشغيل

```powershell
node scripts/testAgentPortal.js --silent
npm run lint
npm run typecheck
npm run check:architecture
node scripts/checkCompanyMobileBrowser.js
node scripts/checkCompanyInteractionsBrowser.js
```

تحتاج فحوص المتصفح إلى خادم التجربة على `http://127.0.0.1:4577`، وإلى `COMPANY_DEMO_PASSWORD` ومسار المتصفح من البيئة. تفحص العروض 320 و360 و390 و430 و1280، والخدمات الستة، وأقسام الإعدادات، والأدوار المختلفة. فحص التفاعلات يراجع اللمس والإغلاق والحقول وتكرار اسم الموظف ومراجعة التحويل، دون تأكيد تحويل حقيقي.

يتحقق فحص PDF من رابط الواجهة ومن محتوى الاستجابة عبر جلسة HTTP تجريبية مستقلة؛ لا ينسخ بيانات جلسة المتصفح. إدارة التنزيل الأصلية داخل Chromium الآلي لم تُعتمد كدليل نجاح، لأن بيئة الفحص أعادت 204 دون حدث تنزيل رغم أن الخادم سلّم ملف PDF صحيحًا.

اختبارات البريد وتيليجرام تحاكي التسليم الخارجي. نجاحها لا يؤكد بيانات SMTP أو إعداد Webhook في الإنتاج؛ يحتاج فحص التسليم الفعلي إلى وجهة تجريبية يحددها المستخدم وتفويض إرسال.

## قياس سرعة التنقل

شغّل `node scripts/measureCompanyNavigation.js --mobile outputs/company-navigation.json` بنفس متغيرات تجربة المتصفح. يحاكي اتصالًا بزمن انتظار 100 مللي ثانية، وتنزيل 200 ألف بايت/ثانية، ومعالجًا أبطأ أربع مرات. يقيس الزمن حتى جاهزية مستند الصفحة ووحداتها، وليس اكتمال تحميل كل الخطوط أو زمن الإنتاج.

في القياس المحلي النهائي بتاريخ 2026-10-27 انخفض زمن الرئيسية من 8.3 إلى 4.1 ثانية، والخدمات من 3.1 إلى 1.4، والإعدادات من 2.6 إلى 1.7، والموظفين من 3.4 إلى 1.4. تتغير الأزمنة حسب الاتصال والجهاز؛ قارن بنفس الإعدادات وترتيب الصفحات.

تحمّل بوابة الشركات التنسيقات الأصلية مباشرة، وتنزل ملفات الصفحة المطلوبة فقط. لا تنزل مكتبة الرسوم المخفية على الهاتف، وتستخدم صورة الشعار الموجودة بحجم 15 كيلوبايت بدل مسار مفقود وصورة بديلة بحجم 1.6 ميجابايت. تُحمّل الرسوم عند الانتقال لعرض سطح المكتب. لم يتغير تخزين الأرصدة أو الصلاحيات أو استجابات الحسابات المالية.

## مراجعة النشر

- راجع التغييرات المرحلية واستبعد `outputs/` وبيانات التجربة والأسرار.
- شغّل `npm audit --omit=dev` مع سلسلة شهادات موثوقة. لا تعطّل تحقق TLS لتجاوز خطأ الشهادة.
- كشف الفحص في 2026-10-27 عن 7 تنبيهات عالية و3 متوسطة و0 حرجة في الاعتماديات الحالية، دون تغيير `package.json` أو `package-lock.json`. تحتاج هذه النتائج إلى معالجة أو تقييم قبل إعلان جاهزية النشر الأمني؛ لم تُجرَ ترقية جماعية للحزم ضمن مراجعة الهاتف.
- افحص تهيئة SMTP والبوت ومولد PDF في بيئة التشغيل قبل تفعيل الاستخدام الحقيقي.

بعد طلب النشر ورفع الإصدار المعتمد، تُنفّذ أوامر السيرفر:

```powershell
git pull --ff-only origin main
if ($LASTEXITCODE -ne 0) { throw 'Git pull failed' }
pm2 restart ahram-pay --update-env
pm2 save
Invoke-RestMethod 'http://127.0.0.1:3000/health/ready'
```

يجب أن تكون النتيجة `status=ok` و`startupReady=True` مع اتصال قاعدة البيانات ومخزن الجلسات. لا يُعاد تشغيل `ecosystem.config.js` كله، حتى لا تُشغّل نسخ API القديمة المتوقفة.

## الرجوع

احفظ مرجع الإصدار السابق قبل النشر. عند خلل في البريد أوقف العامل عبر `COMPANY_REPORT_EMAIL_ENABLED=false` وأعد تشغيل التطبيق لتطبيق الإعداد، مع الاحتفاظ بسجلات التسليم. يمكن إيقاف كل اتصال تيليجرام من إعداداته.

عند الرجوع عن الواجهة، احتفظ بإصلاحات تحديد الأدوار والتحقق من الصلاحيات. إرجاع منطق قديم يعتبر صلاحية التقارير ملكيةً قد يمنح حسابًا حديثًا صلاحية غير مقصودة؛ لا ترجع التطبيق كله تلقائيًا بعد إنشاء حسابات بالسياسة الحديثة دون مراجعة هذه الحسابات. لا تُحذف المجموعات الجديدة أو سجلاتها كخطوة رجوع.
