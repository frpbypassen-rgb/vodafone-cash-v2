# Customer portal release

Run `scripts/restartAhramAfterDrain.ps1` in Windows PowerShell as Administrator from the existing production project. Default mode is read-only; `-Apply` explicitly authorizes a brief admission pause and managed PM2 restart. This is not zero downtime. All customers must continue to use HTTPS through the IIS site, and the existing public TCP 3000 firewall protection must remain enabled.

The script requires the same ready PID through local health, PM2 and public HTTPS, the expected application directory, one PM2 fork runtime and complete empty transaction/queue observations. Missing inspection data, pending/processing/accepted/deposit_pending records, delayed jobs or queued work block restart. It never settles, cancels, refunds, removes or resends financial operations. Do not bypass a busy result.

Apply temporarily adds one first-priority IIS rewrite rule returning 503, confirms that response through public HTTPS, then requires two further empty observations before stopping PM2. Existing execution can finish during the observation window; if work appears, the script removes its own gate and aborts before stopping. It does not stop the IIS site or change DNS, mail or firewall rules. New HTTPS requests, including API calls, receive a temporary unavailable response while admission is closed.

After PM2 restarts, local readiness, port/PID ownership, project path and background flags must match before the gate is removed. No force termination is used. If startup fails after a stop attempt, admission remains closed; inspect the printed gate name and `pm2 logs ahram-pay --lines 60 --nostream` before reopening. Filesystem publication and restart are separate: fast-forward merges stop on conflicting server edits and never discard them. There is no automatic financial-data or source rollback.

No dependency manifest/lock change is included in this release, so do not run npm ci against live dependencies. Existing SMTP, Telegram and VAPID configuration is reused. Preserve `.env`, private document storage and server-specific financial extensions. A new unique customer-email delivery job index is created during startup; there is no financial migration.

Validation includes focused portal/login/notification/document tests, empty-runtime guard tests and PowerShell AST parsing. IIS mutation and real production restart require the server execution and health results; they are not validated by local tests. The gate uses Microsoft's [IIS configuration API](https://learn.microsoft.com/en-us/iis/manage/scripting/accessing-configuration-sections-using-microsoftwebadministration-mwa) and [CustomResponse action](https://learn.microsoft.com/en-us/iis/extensions/url-rewrite-module/url-rewrite-module-configuration-reference#customresponse-action).
