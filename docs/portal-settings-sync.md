# إعدادات البوابة المشتركة مع الإدارة

تظهر لوحة **إعدادات البوابة والتكاملات** للإدارة الرئيسية في صفحة تفاصيل الشركة/الوكيل وفي صفحة تعديل بياناته. كانت أدوات التكامل موجودة في التفاصيل فقط، وكانت إدارة Telegram القديمة تعرض سجل الربط القديم دون الحسابات المتعددة التي تظهر في البوابة.

## مصدر البيانات والسلوك

- تفعيل API وWebhooks يقرأ ويكتب `integrationAccess` على الشركة أو الوكيل نفسه. مصادقة API وبوابة Webhooks تتحققان من هذه القيم على الخادم. التوكن الكامل لا يظهر في ملخص الإدارة؛ تغيير المفتاح يبطل القديم.
- عناوين الكشف اليومي وحالة التحقق والإرسال تُقرأ من `CompanyReportEmail` أو `AgentReportEmail`. يظهر اسم الحساب المستلم لأن الاشتراك مرتبط بصاحب الحساب أو الموظف المخول، وليس بريد التواصل التجاري أو بريد OTP. لا تتيح الإدارة تجاوز تأكيد ملكية البريد.
- حسابات Telegram الحديثة والربط القديم تظهر معًا. تغيير الاسم أو استقبال الإيصالات يكتب السجل نفسه الذي تستخدمه البوابة والإرسال، ويحافظ إيقاف Telegram على إعداد WhatsApp في الربط القديم. تم منع مسار تعديل Telegram القديم من الكتابة العمياء للشركات والوكلاء؛ يستخدمان اللوحة المشتركة.
- إشعارات الويب تعرض الاشتراكات الحقيقية للمتصفحات، دون كشف endpoints أو مفاتيح الاشتراك. خيار البوابة يحفظ حالة الاشتراك على الخادم بدل localStorage. إنشاء الاشتراك يحتاج دعم المتصفح وإذنه ومفاتيح VAPID، ولا تستطيع الإدارة منح إذن النظام. اكتمال إرسال إشعار أو فشله مؤقتًا لا يعيد تشغيل اشتراك أوقفته الإدارة أثناء الإرسال.
- يظهر ملخص بيانات المنشأة، وحسابات الدخول وAuthenticator وبريد OTP والمظهر وروابط Webhooks. هذه ليست نسخًا جديدة من الإعدادات أو كلمات المرور. يبقى تغيير معلومات المنشأة في محرر البيانات الأصلي، وتأكيد الحماية في مسارات الأمان الموجودة.
- خيار كثافة الجداول في بوابة الوكيل يُحفظ في `preferences.density` لحساب الدخول، ويظهر في ملخص الإدارة ويُطبّق عند تحميل بقية الصفحات. يحميه `displayRevision` مستقل. تبقى إعدادات العملاء الأفراد القديمة خارج هذا التغيير.

## منع التعارض

لكل مورد إعدادات رقم إصدار مستقل؛ تفعيل التكاملات له `integrationAccess.revision`، وإعدادات البريد وTelegram والمتصفح لها `settingsRevision`. السجلات القديمة التي لا تحمل إصدارًا تبدأ من صفر. تحفظ الواجهات الإصدار الذي قرأته وتُجري كتابة شرطية وزيادة ذرية؛ الحفظ المتأخر يرجع `409 SETTINGS_CHANGED` دون إعادة المحاولة تلقائيًا بالاختيارات القديمة. سجلا البريد وTelegram يعرضان آخر مُعدّل ووقت التعديل، ويُسجل تعديل الإدارة في سجل التدقيق دون أسرار.

بيانات المنشأة المشتركة محمية كذلك بـ`profileRevision` في نموذج الإدارة ونموذج البوابة، مع شرط على حفظ وثيقة Mongoose. يعرض النموذج القديم تنبيهًا للمراجعة عند تغير البيانات؛ لا يعيد تحميل قيم قديمة فوق الجديدة. لا يُستخدم `updatedAt` العام كإصدار حتى لا تعطل تغييرات الرصيد أو محاولات الإرسال حفظ إعداد آخر.

تُحدّث الحالة عند العودة للصفحة وبفاصل 15 ثانية أثناء ظهور التبويب. تفعيل API وإيقافه يُفرضان على الخادم قبل اكتمال تحديث العرض. لا تستبدل لوحة الإدارة خيارات غير محفوظة أثناء التحديث الخلفي، ولا تستبدل البوابة عنوانًا أو اسمًا أثناء تحريره. تغير إعداد مورد لا يعطل حفظ مورد مستقل.

## حدود الوصول

`GET/POST /admin/accounts/:type/:id/portal-settings` يقبل نوعي `company` و`agent` فقط، ويتطلب جلسة الإدارة الرئيسية وCSRF للكتابة. تعزل الاستعلامات الحساب والمنشأة والموارد التابعة؛ لا يمكن تعديل مورد بإرسال معرفه من حساب آخر. بيانات الاستجابة محددة صراحة ولا تشمل توكن API أو مفاتيح Webhooks أو أكواد تأكيد البريد/Telegram أو أسرار MFA. الاستجابات `private, no-store`.

## التحقق

```powershell
npx jest tests/portalSettingsRevision.test.js tests/portalSettingsSync.test.js tests/merchantIntegrationRoutes.test.js tests/adminAccountManagementService.test.js tests/companyWebPushService.test.js tests/agentTelegram.test.js tests/companyEmailDelivery.test.js --runInBand
node scripts/checkPortalSettingsSyncBrowser.js
```

اختبارات API تستخدم MongoDB مؤقتًا وتختبر التفعيل والإيقاف والتدوير ورفض التوكن القديم، والمزامنة في الاتجاهين، والحفظ المتزامن، وتأكّد البريد، وعزل المنشآت وCSRF وصلاحيات الإدارة، وبيانات المنشأة والسجلات القديمة. فحص المتصفح مقيد بخادم المعاينة `127.0.0.1:4577` وقاعدة `ahram_company_mobile_demo_v2` المحلية ويتطلب `MONGO_URI` و`PUPPETEER_EXECUTABLE_PATH`. ينشئ حساب إدارة وشركة ووكيل وسجلات إشعارات مؤقتة ويزيلها بعد الفحص. لا يرسل رسائل بريد أو Telegram أو إشعارات خارجية؛ يفحص الواجهات الحقيقية بالوضعين الليلي والنهاري وعروض 320 و390 و430.

لا تتطلب الإضافة ترحيل بيانات يدويًا أو اعتماديات جديدة. يجب تحديث صفحة الإعدادات المفتوحة قبل النشر عند ظهور تعارض من عميل قديم لا يرسل رقم الإصدار.
