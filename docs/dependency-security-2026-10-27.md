# معالجة تنبيهات الاعتماديات — 2026-10-27

## النتيجة والنطاق

أظهر `npm audit` بعد التحديث صفر تنبيهات في اعتماديات التشغيل والتطوير: حرجة وعالية ومتوسطة ومنخفضة. قبل المعالجة كانت اعتماديات التشغيل تُظهر 7 حزم عالية و3 متوسطة؛ كشف الفحص الذي يشمل التطوير أيضًا حزمة Handlebars بتصنيف حرج.

استُخدمت تحديثات متوافقة مع نطاقات الحزم المباشرة، دون `--force` ودون تعطيل فحص الشهادات أو استثناء تنبيهات من التدقيق. رُفعت الحدود الدنيا لثلاث حزم مباشرة، وحُدّث `package-lock.json` للحزم المتفرعة. لا توجد تعديلات على منطق التحويلات أو الصلاحيات أو قواعد البيانات ضمن هذه المعالجة.

## التحقق من الوظائف

- نجح فحص حي لـ27 صفحة في بوابة الشركات بعروض 320 و360 و390 و430 و1280، مع تسجيل الدخول والبحث والموظفين وقائمة المزيد وتنزيل PDF رسمي وقيود الأدوار.
- نجح فحص التكاملات للشركات والوكلاء على الهاتف: تفعيل الإدارة، تغيير التوكن وإبطال السابق، الإلغاء، وفتح Webhooks.
- نجح `checkDependencySecuritySmoke.js`: استقبال JSON، رفض جسم gzip تالف دون إسقاط الخادم، رفع ملف، رفض الحجم الزائد، قطع طلب أثناء fileFilter غير متزامن، تجهيز بريد عربي ومرفق PDF عبر نقل محلي، وتشغيل المتصفح وتوليد PDF. لا يرسل الفحص بريدًا أو تحويلًا ماليًا أو Webhook خارجيًا.
- نجحت فحوص lint وTypeScript وسياسة البنية.

## حدود الفحص الشامل ومقارنة الإصدار السابق

الفحص الأول لجميع الاختبارات شمل 277 مجموعة و2275 اختبارًا؛ نجح 2249 وفشل 26. بعد ضبط مسار Chrome وإعادة حالات المهلة، نجحت اختبارات سلامة الحسابات المالية وقالب البريد ومتصفح المنفذين. ظهر إخفاق مهلة عابر في اختبار واجهة واتساب؛ نجح عند إعادة المقارنة.

لتمييز أثر التحديث، أُنشئت نسخة معزولة من المرجع `d75f42e` مع ملف القفل القديم واعتمادياته الأصلية، خارج مستودع العمل. شُغلت مجموعات الإخفاقات المتبقية في النسختين بنفس إعداد المتصفح. **تطابقت الإخفاقات الخمسة عشر بأسمائها**: 6 مجموعات فاشلة، مجموعة ناجحة، 15 اختبارًا فاشلًا و68 ناجحًا في كل نسخة.

المجموعات التي تحتاج صيانة مستقلة هي `runtimeIsolation` و`isolationRound2` و`centralLedgerPage` و`customerPortalMobile` و`ownerEmailOtpAdminUi` و`otpSecurity`. تشمل تجهيزات تفعيل Webhooks، وتوقعات واجهات قديمة، وسياق قوالب ناقص، وتوقعات المسار الفوري للمنفذ. لم تُغيّر الاختبارات أو تُضعف شروطها لإخفاء هذه الإخفاقات. لا يُصنّف الفحص الشامل كله على أنه ناجح، رغم عدم ظهور إخفاق جديد بسبب ترقية الحزم في المقارنة.

## إعادة الفحص والتثبيت

```powershell
npm ci
npm audit
npm run lint
npm run typecheck
npm run check:architecture
node scripts/checkDependencySecuritySmoke.js
```

يتطلب اختبار المتصفح Chrome المدعوم عبر `PUPPETEER_EXECUTABLE_PATH` أو المتصفح الذي تثبته Puppeteer. إذا استُخدم تخطي تنزيل المتصفح في بيئة النشر، يجب ضبط مساره صراحةً. فشل TLS في npm يُعالج بسلسلة شهادات موثوقة، دون تعطيل `strict-ssl`.

عند نشر هذا الإصدار يجب تنفيذ `npm ci` بعد السحب وقبل إعادة تشغيل `ahram-pay`؛ إعادة التشغيل وحدها لا تُحدّث الحزم المثبتة.
